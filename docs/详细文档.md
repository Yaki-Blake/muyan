# 幕言 · 系统声音实时字幕

抓 Windows 正在播放的声音（WASAPI 环回），走语音识别 API，把结果显示成一块置顶悬浮的字幕弹窗。

不录麦克风，只抓扬声器输出。看视频、开会、听播客都能用。

字幕弹窗会把这次识别出来的每一句都留着，可以像看聊天记录一样上下翻。

---

## 快速开始

```powershell
cd "项目目录"
python -m pip install -r requirements.txt
python -m muyan
```

或者双击 `启动.bat`（会先自检再启动）。

不想装 Python 就下载 Releases 里的「muyan-windows-portable.zip（免安装版）」，里面是单个 exe。

## 支持的服务商

| 服务商 | 模式 | 实测 |
|---|---|---|
| **云知声 U2-ASR** | WebSocket 真流式 | ✅ 推荐。逐字增量、自动标点断句、亚秒延迟 |
| 本地 faster-whisper | 离线 | ✅ 可用。不要 Key，但中文一般，2-4 秒延迟 |
| 阿里云百炼 Paraformer | WebSocket 真流式 | 协议已实现，未用真 Key 验证 |
| 硅基流动 / 百炼兼容 / 智谱 | 分片上传 | 标准 `/audio/transcriptions`，未用真 Key 验证 |
| 云知声 Token Hub 异步 | 任务轮询 | ⚠️ 能用但延迟 5-15 秒，不适合实时字幕 |
| 测试模式 | 不联网 | 验证音频链路和界面 |

### 云知声实时接口（推荐）

实测协议（2026-11-23 验证通过）：

```
wss://maas-api.unisound.com/v2/audio/asr/realtime?model=u2-asr
Authorization: Bearer <api_key>

→ {"type":"start","data":{"format":"pcm","sample":"16k","variable":"true",
                          "punctuation":"true","language":"zh-CN"}}
→ 持续发二进制 PCM（16k / 16bit / 单声道）
→ {"type":"end"}

← {"type":"variable","text":"今天我们讨论","end":false}   ← 累积全文，整行替换
← {"type":"fixed","text":"今天我们讨论一下第三季度的财务报表，","end":false}  ← 定稿一句
← {"type":"fixed","text":"...","end":true}                ← 本轮结束
```

关键点：`variable` 的 text 是**从本轮开始的累积全文**，不是增量。`fixed` 才是定稿。

Key 在云知声控制台「按量计费 > API Key 管理」里建，`tp-` 开头。

## 怎么用

1. 启动后主窗口点「开始字幕」
2. 字幕弹窗出现在屏幕上，把鼠标放上去就能操作：

| 操作 | 效果 |
|---|---|
| 拖面板中间 | 移动整个弹窗，位置自动记住 |
| 滚轮 | 上下翻历史，一格 1.15 行，缓动跟手（翻上去后新到的字**不会**把视图拽走） |
| Ctrl + 滚轮 | 改字号（10–96pt，自动记忆） |
| Shift + 滚轮 | 整体缩放弹窗，比例不变 |
| 拖四边 / 四角 | 自由改宽高和比例；按住 Shift 拖角保持比例 |
| 拖右侧滚动条 / 点它 | 快速跳转（拖到最底部就恢复自动跟随） |
| 右键 | 滚到底部、复制全部、保存成 txt、清空、回中、打开设置 |

3. 关掉主窗口不退出，收进托盘；右键托盘图标可以重新打开或退出

### 标点和断句为什么快

云知声的标点是服务端在「确认你这句话说完了」之后才给的（`fixed` 帧），而判停要等 VAD 安静下来，通常还要再压 0.8–1.5 秒。等它的时候屏幕上只会滚过一大串没标点的字，标点和断句都迟到。

现在本地加了一层「提前断句」：

- 一边收服务端的累积文本（`variable`），一边盯着它有没有停稳
- 文本停稳 ≈0.2 秒且结尾是 `。！？…；` → 立刻把这段定稿（含标点）
- 停稳 ≈0.3 秒且结尾是 `，、：` → 也定稿，长句不会拖成一大坨
- 一路没有标点又说个不停，攒到 28 字左右 → 自己补一个逗号断开
- 服务端稍后回 `fixed` 时按「已输出字数」去重，只补剩下的，不会重复也不会吞字

效果是标点和换行比原来早半拍出现，服务端那帧只当兜底。不喜欢可以在设置里关掉「提前断句」，或把等待从 320ms 调大（更稳）／调小（更快）。

### 字幕弹窗的行为

- **一直累积**：定稿的每句都留在面板里（本次运行最多 2000 段，防挂机吃内存），不会只显示最近几行
- **滚得顺**：滚轮只改目标位置，画面每帧 16ms 朝目标缓动过去，不会一格一格跳；**不做行对齐吸附**，停在哪儿就是哪儿
- **滚动时不掉帧**：动画期间每段字用字形位图直接贴上去，静止时再切回矢量文字，实测单帧 1.7ms（直绘 11ms）
- **不跳**：停在底部时自动跟最新一句；一旦往上翻，视图就钉住不动，新字只往文档末尾追加
- **半句淡一点**：正在识别的那句颜色略淡，定稿后变成正常白色
- **不会吃掉屏幕外的窗口**：换显示器/拔显示器后会自动把弹窗拉回可见区域

### 设置项

- **服务商**：默认云知声实时。没有 Key 就切「本地 faster-whisper」
- **分片时长**：只对分片模式生效。默认 4 秒（实测甜点：整句完整，推理跟得上）
- **断句**：「提前断句」默认开；「等待」320ms 是判断「这句话停稳了」的门槛。调小块更快但可能切到半句，调大块更稳但标点会晚一点
- **输出设备**：默认扬声器即可。多声卡时可指定
- **字幕外观**：右侧有实时预览，改哪一项都能立刻看到
  - 字体、字号、行距、字距、对齐方式（长段落建议左对齐）
  - 描边粗细与描边色（深色背景下白色文字更清晰）
  - 底色与「浓度」、圆角、左右/上下留白
  - 文字始终不透明，只让底色透，保证字不糊
  - 面板宽高
  - 「显示状态点」：左下角小绿点表示系统声音正在流入，琥珀色表示当前安静
  - 「空白时隐藏」：没有字幕时整块完全透明，并且不挡鼠标点击
  - 「自动跟随最新」：关掉后新字不会把视图滚走，得自己往下翻
  - 改乱了点「恢复默认外观」一键恢复推荐样式

> 从旧版「字幕条」升级时会自动把 960×200 / 26pt / 居中 改成 960×360 / 22pt / 左对齐 / 浓度 0.95，只改一次。

## 稳定性（2026-11 重构）

之前的版本会「用着用着就不出字幕」，根因有四个，现在都堵上了：

| 现象 | 根因 | 现在怎么处理 |
|---|---|---|
| 字幕突然静止，界面还写着「正在识别」 | 发送线程一次网络失败就 `return`，线程死掉后重连成功也没人喂音频 | 发送线程常驻，失败只废掉当前连接，交给连接线程重连 |
| 安静十几秒后整条链路停掉 | `recv` 超时被当成断线，触发 `error`，主窗口直接 `stop()` | 读循环 1 秒轮询，超时只算「暂时没消息」；30 秒无回包且确实说过话才重建连接 |
| 换耳机/蓝牙掉线后永久没字幕 | 采集线程异常后直接结束，没人重启 | 采集线程内部自动重开设备；主窗口 2 秒一次看门狗，线程死了就重建 |
| 网络抖动一次就崩 | 可自愈的异常走了 `error`（致命） | 网络类异常走 `warn`，只提示不中断；只有鉴权失败/缺依赖才真停 |

另外还有两个小保护：

- 每轮 `end` 后重开会话时，用「轮次号」丢掉重开前抓到的旧音频，避免重复字/错位
- 主窗口状态栏会显示重连、恢复过程；面板左下角的点会反映音频是否在流动，一眼能看出是「安静」还是「真卡了」

### 切视频 / 换播放源之后

这是最容易「字幕突然不动」的时刻，三个环节都可能断，现在各自都能自己修：

| 环节 | 为什么会断 | 现在怎么处理 |
|---|---|---|
| 环回采集 | 旧视频关掉的一瞬间，播放设备进入空闲，WASAPI 环回句柄跟丢——还能读到数据，但全是纯数字零 | 连续 2.5 秒读到「一个非零采样都没有」就判定句柄失联，自动重开设备；重开后还在静音就不再反复折腾（避免暂停时每 10 秒重开一次） |
| 识别会话 | 音频照发，但服务端认不出这是新的一轮，干脆不回包 | 只要「有声的音频块连续 5 秒没有任何回包」就重建连接（原来要干等 30 秒）；重连后重新发 `start`，面板历史不受影响 |
| 播放设备 | 切到耳机/蓝牙，默认扬声器换了 | 每 2 秒对比一次默认设备名，变了就重开 |

采集一旦重开，主窗口会顺手把识别连接也换一条（`restart_connection`），所以切换视频后通常 2–4 秒就接上字幕，不用手动停停开开。

      mock.py             测试模式

免安装 exe 在 Releases 的「muyan-windows-portable.zip（免安装版）」里，不包含在源码仓库中。

第一次运行会自动把旧版 `%APPDATA%\ARTEX\config.json` 搬过来，Key 和面板尺寸不用重配。

## 已知限制

- 只支持 Windows（依赖 WASAPI 环回）
- 云知声实时接口的 `variable` 中间结果会有抖动（"我我们讨论一一下"），`fixed` 定稿是干净的。提前断句只在文本停稳 0.2 秒以上才切，抖动的字基本落不到屏幕上
- 本地 small 模型中文数字容易听错（"百分之十二" → "百万元"）。medium 更准但推理比音频还慢，不划算
- 静音段会被跳过（RMS 阈值 90），不会白花钱
- 分片模式识别跟不上时会丢分片，状态栏会提示，调大分片时长可缓解
- 历史只存在内存里，关掉程序就没了；要留档用右键「保存为 txt」
- 打开「鼠标穿透」（`click_through`）后面板不再响应滚轮/拖动，要交互得先关掉
- 成品 exe 为了体积没打包 faster-whisper，**本地离线模式只在源码方式下可用**；exe 里用云知声 / 百炼 / 硅基流动这些联网模式

## 打包成品

```powershell
cd "项目目录"
.\build.ps1
```

产物是 `成品\幕言.exe`：**单个 exe，PySide6 全打进去，约 68 MB**，双击就能跑，不用装 Python、不用启动脚本。这个目录默认不进 Git，发布时作为 Release 的压缩包上传。
打包时排除了 faster-whisper / ctranslate2 / av 这一串离线识别依赖，所以体积能压到 68 MB 左右。单文件模式启动时会把内容解到临时目录，首次打开约 2 秒。
